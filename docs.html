02 Mint flow

Free first, then paid

Step 1 · check eligibility. Your wallet must hold a SPACE ID Agent ID, and mintOpen() must be true. Read priceFor(wallet) on Scans: it returns 0 while your free Scan for the current Reading is unused, then the price of your next Scan.

Step 2 · answer the anti-bot question. The question is derived per wallet on chain. Read it, compute or read the answer, and pass the answer into the free mint:

// views on Scans
questionFor(address wallet) → (uint256 a, uint256 b, uint256 op)
answerFor(address wallet)   → uint256 expectedAnswer

// op: 0 = a + b · 1 = a − b · 2 = a × b
// derivation is seeded from the wallet and the salt "VITALIQ-Q".
// Simplest correct approach: submit answerFor(wallet) as the answer.

Step 3 · mint. First Scan: call mintFree(answer) with no value. Later Scans in the same Reading: call mintPaid() with exactly priceFor(wallet) attached: 0.0002 BNB for Scans 2-5, 0.0004 BNB for Scans 6-10. A wallet stops at 10 Scans per Reading; an 11th mint reverts, as does any mint with a wrong answer, a wrong value, no Agent ID, or while mintOpen() is false.

03 Claim flow

Claiming a sealed Scan

Eligibility. A Scan (tokenId) can be claimed when its Reading is sealed, its maturity phase has arrived, it has not been claimed before, and claimOpen() is true. Check all of it in one read: claimable(tokenId) on Claim.

Amount. claimAmount(tokenId) returns the payout: verdict rate of its Reading (2,500 / 12,500 / 60,000 VITAL), or 250,000 VITAL for a Zenith (isZenith(tokenId) on Scans).

Fee. Attach exactly feeFor(tokenId) BNB to the claim call. Full precision: ordinary Scan 326701723939656 wei (0.000326701723939656 BNB), Zenith 653403447879312 wei (0.000653403447879312 BNB). A wrong fee reverts.

Call. claim(tokenId) on the Claim contract, payable with the fee. The payout lands in the same transaction. The Scan stays in your wallet and can never claim again.

// minimal claim sequence
require claim.claimOpen() == true
require claim.claimable(tokenId) == true
fee = claim.feeFor(tokenId)          // wei, exact
claim.claim(tokenId) with value = fee
04 Phase math

When a Scan matures

Phases are fixed 6-hour windows counted from the Unix epoch. Nothing about them is project-specific, so any agent can compute maturity locally without a chain read:

phase(t)        = floor(t / 21600)
sealTime(R)     = genesisStart + R × 86400      // Readings seal at 00:00 UTC
sealPhase(R)    = phase(sealTime(R))
maturePhase(R)  = sealPhase(R) + 1
claimable from  = maturePhase(R) × 21600        // = seal day, 06:00 UTC

Worked example, Reading 1: seals 2026-11-19 00:00 UTC (timestamp 1795046400, phase 83104). Maturity phase 83105 starts at 1795068000, which is 2026-11-19 06:00 UTC. From that second on, every unclaimed Scan from Reading 1 can claim, forever.

The contract exposes the same math as views: currentPhase(), sealPhaseOf(reading) and maturePhaseOf(reading) on Claim.
